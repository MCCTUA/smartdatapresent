สถานะปัจจุบันหลังเริ่มดำเนินการตามแผนนี้

  • Phase 1 ทำแล้ว: สำรวจ admin/frontend header paths และเพิ่ม contract ใน static guard
  • Phase 2 ทำแล้ว: Admin header ถูก override ที่ block header แบบยังรักษา Django blocks สำหรับหน้าเฉพาะ เช่น password change
  • Phase 3 ทำแล้ว: Frontend base เรียก components/app_shell.html เพื่อรวม sidebar/top nav เป็น shell include
  • Phase 4 ทำแล้วบางส่วน: เพิ่ม tests สำหรับ static guard, admin language switcher, logout order และ password change userlinks compatibility
  • Public/auth cleanup ทำแล้ว: login และ PDPA policy ใช้ semantic classes แทน utility class ยาวในจุดหลัก พร้อม test guard
  • ยังต้องทำด้วยตา: manual responsive QA บน admin, dashboard, map, device, notification, public register และ login pages

1

Phase 1: Inventory & Contract

สำรวจทุก template ที่มี header/top-nav/user-tools ซ้ำ และนิยาม contract ว่า include แต่ละตัวต้องรับ context อะไรบ้าง

  • หา markup ซ้ำใน templates/admin/*, templates/components/*, dashboard/public pages
  • แยก context ระหว่าง anonymous, platform owner, dealer, customer, staff/admin
  • กำหนด fallback กรณีไม่มี account, ไม่มี language, หรือไม่มี theme state
low risk read-only first
2

Phase 2: Admin Header Include

ย้าย header ของ Django Admin มาอยู่ใต้ SmartLight-owned header block และแตกส่วนที่เปลี่ยนบ่อยเป็น partial ย่อย โดยรักษา Django admin block เดิมให้มากที่สุด

  • สร้าง block-compatible admin header ใน templates/admin/base_site.html และ include ย่อยสำหรับ links, language, theme, logout
  • ย้าย responsive grid ของ #header, #branding, #user-tools ไปไว้ที่ CSS กลาง
  • รักษา order: Welcome, links, theme, language, logout
admin only theme-safe
3

Phase 3: Frontend Header/Shell Include

รวม dashboard/top-nav/sidebar header ให้ใช้ component contract เดียวกัน แต่ยังไม่ผูกกับ admin CSS

  • กำหนด app_shell.html สำหรับ frontend dashboard pages เพื่อรวม sidebar และ top nav ใน include เดียว
  • รวม search, alert button, user menu, language switcher เป็น child components
  • ใช้ container token เดียวกับ dashboard layout เพื่อให้ desktop ไม่แคบเกิน
frontend only responsive
4

Phase 4: Cleanup & Guard

ลบ duplicated markup/CSS ที่เหลือและเพิ่ม test guard กัน regression จาก include path หรือ static asset order

  • เพิ่ม/ปรับ tests สำหรับ admin language switcher, theme toggle, logout order
  • เพิ่ม static guard สำหรับ include CSS ที่ต้องโหลดก่อน/หลัง
  • รัน related tests และ full suite ใน Docker ก่อนปิดงาน
test required safe rollout

ความเสี่ยงที่ต้องคุม

CSS specificity ชนกัน

โดยเฉพาะ Django Admin มี selector เดิมเยอะ ต้องไม่แก้ด้วย !important เพิ่มถ้าไม่จำเป็น

Context ไม่ครบ

header frontend กับ admin ใช้ข้อมูลคนละชุด ต้องมี fallback ไม่ให้ template พังเมื่อ user/account/language ไม่มี

Responsive regressions

ต้องเช็ค 360px, 768px, 1024px, desktop wide เพราะ header มี controls หลายกลุ่ม

visual QA required do not mix admin/frontend shell

ตัวอย่าง Before / After

แนวทางคือเปลี่ยนจาก markup ซ้ำในหลายไฟล์ เป็น include ที่มี contract ชัดเจน

Before:
base_site.html
  <header id="header">
    branding + user-tools + theme + language + logout
  </header>

After:
base_site.html
  {% block header %}
    SmartLight-owned admin header structure
    {% block userlinks %}
      {% include "admin/components/header_userlinks.html" %}
    {% endblock %}
  {% endblock %}

admin/components/header_userlinks.html
  {% include "admin/components/header_userlinks_links.html" %}
  {% include "admin/components/header_userlinks_controls.html" %}

base.html
  {% include "components/app_shell.html" %}

Definition of Done

  • Admin header อยู่ใต้ SmartLight-owned header block และใช้ partial ย่อย โดยยัง block-compatible กับ Django admin
  • Frontend dashboard header/sidebar/top-nav ใช้ component contract เดียว ไม่ duplicate markup หลัก
  • Responsive breakpoint ของ branding, user tools, controls และ container เป็น pattern เดียว
  • Dark/light mode ของ theme toggle และ header controls ไม่ค้างสี hardcoded
  • Related tests และ full Django test suite ผ่านใน Docker
  • มีรายการ manual QA URLs สำหรับตรวจภาพจริงหลัง deploy/restart

เอกสารนี้เป็น implementation plan สำหรับ phase ถัดไป ไม่ใช่ code change ของ header include เอง และควรใช้ร่วมกับ prompts/INDEX_CANONICAL.html
