Implementation source plan

InfluxDB เป็น telemetry store, Django ยังเป็น business API

เอกสารนี้อธิบายแผนแก้ระบบให้รองรับ telemetry scale โดยไม่ทำให้ logic ซ้ำซ้อน: InfluxDB เก็บ time-series, PostgreSQL เก็บ latest/business state, Device State Engine ตัดสิน OK/error/fault, และ UI ทุกหน้าอ่านผ่าน Django API เท่านั้น.

Non-negotiable rule

UI must not query InfluxDB directly.

ทุกหน้า HTML ต้องเรียก Django Ninja/API layer เพื่อ enforce tenant, package, visible_until, retention, role, export และ action lock ก่อนเสมอ.

InfluxDB ownsTelemetry history

Voltage, current, power, kWh, PF, RSSI, runtime, raw/downsampled time-series.

PostgreSQL ownsBusiness state

DeviceLatestState, ActiveIssue, FaultOccurrence, WorkOrder, Notification, AuditLog.

Django ownsPolicy + API

PackageTelemetryPolicy, EntitlementPolicy, dashboard/report/query/control endpoints.

EMQX ownsProduction ingest

Large-scale MQTT firehose consumed by telemetry workers, not direct Django request per lamp.

Target data flow

Production pipeline ที่ต้องทำจริง

MQTT -> Worker -> InfluxDB/PostgreSQL -> API -> UI
1Device/Gateway

ส่ง telemetry ตาม package/gateway cadence หรือ batch payload. ห้าม assume ว่าทุกโคมส่งเท่ากัน.

2EMQX

รับ MQTT topics ระดับ production scale และแยก tenant/device/account scope ใน topic/payload.

3Consumer

อ่าน stream, validate schema, dedupe event_id, resolve package policy, normalize units/timezone.

4InfluxDB

batch write raw/downsampled telemetry ตาม retention และ sampling policy.

5State Engine

คำนวณ latest state และ issue rules เช่น lamp_state_unconfirmed after debounce, command timeout, offline.

6PostgreSQL

upsert latest state, active issue, notification, audit, work-order relationship.

7Django API/UI

Dashboard, Map, Device, Faults, Reports query ผ่าน API กลางพร้อม package/entitlement gate.

Large scale path:
Devices/Gateways -> EMQX -> telemetry_consumer -> PackageTelemetryPolicy
-> InfluxDB raw/downsample write
-> DeviceStateEngine / IssueRuleEngine
-> PostgreSQL DeviceLatestState + ActiveIssue
-> Channels delta event
-> Django Ninja query APIs -> UI

Small/dev path:
Simulator/Node-RED/manual import -> Django Ninja ingest endpoint
-> same normalize/policy/state services
-> same InfluxDB/PostgreSQL outputs

Code change plan

แก้ code เป็นลำดับเพื่อไม่พลาด

Already addedDocker + settings

docker-compose.yml มี service InfluxDB แล้ว. .env และ settings.py มี INFLUXDB_* แล้ว.

Step 1Add client dependency

เพิ่ม InfluxDB Python client ใน dependency แล้วทำ wrapper service กลาง ไม่เรียก client ตรงจาก views/templates.

Step 2PackageTelemetryPolicy

Resolver จาก Account/PackageTier เพื่อคืน sampling, visible range, retention, action lock, export permission.

Step 3NormalizedTelemetryEvent

สร้าง schema/service สำหรับ normalize timestamp, unit, tenant, account, device_id, event_id, source.

Step 4Influx writer/query service

Batch write raw points, query time-series with Flux/API, support bucket/agg/group/compare.

Step 5Telemetry consumer

MQTT consumer/worker อ่าน EMQX stream, dedupe, resolve package, write InfluxDB, update PostgreSQL state.

Step 6State + issue engines

DeviceLatestState and ActiveIssue remain PostgreSQL business state. Do not create issue every telemetry point.

Step 7Django Ninja query APIs

Dashboard timeseries, map state, device list, faults, reports query through API with package/entitlement applied.

Step 8Channels delta

Push only state changes, issue changes, command ACK, and aggregate/delta. Do not push every raw telemetry point to UI.

API contract

Django APIs ที่ต้องมีเพื่อผูก UI

PolicyGET /api/telemetry/policy

Resolved package sampling, retention, visible range, software/hardware state, action lock.

TimeseriesGET /api/dashboard/timeseries

Metric, range, bucket, aggregate, group_by, compare, overlays. Query InfluxDB behind API.

StateGET /api/devices/state

DeviceLatestState list for map/device-list/dashboard. Query PostgreSQL latest state.

IssueGET /api/faults/issues

Active issue queue from Issue Rule Engine only.

ReportsGET /api/reports/preview

Preview table uses same filter/export contract, then CSV/PDF uses identical query.

ExportPOST /api/exports/card

Card export receives card_id + current filter context and applies package/role policy.

Failure prevention

Checklist กันพลาดตอนลง code จริง

Must pass before merge

1. Docker compose config passes
2. InfluxDB healthcheck passes
3. PackageTelemetryPolicy tests pass
4. Ingest idempotency tests pass
5. Query clamp by visible_until tests pass
6. UI pages do not call InfluxDB directly
7. Exports use same filter contract as preview
8. Expired package locks actions but ingestion continues

Do not implement this way

Do not write every raw telemetry point to PostgreSQL.
Do not let dashboard/map/device-list calculate fault independently.
Do not create a new active issue every second for the same fault.
Do not let frontend bypass Django API to query InfluxDB.
Do not hardcode polling interval in UI cards.
