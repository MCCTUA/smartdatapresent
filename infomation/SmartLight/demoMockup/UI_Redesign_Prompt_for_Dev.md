# Prompt สำหรับ Claude Code / Claude Design — ปรับ UI SmartLight ให้เป็นมิตร

> **บริบท:** ชุดหน้าจอ HTML demo ระบบบริหารไฟถนนอัจฉริยะ (dashboard, faults, energy, zones, remote_control, reports, backoffice ฯลฯ)
> **ลูกค้าปลายทาง:** เจ้าหน้าที่ อปท. (เทศบาล/อบต.) — กองช่าง, ปลัด, นายก — **ไม่ใช่ developer** หลายคนไม่คุ้นศัพท์เทคนิค/ภาษาอังกฤษ
> **ปัญหาปัจจุบัน:** หน้าจอแน่นเกินไป ตัวอักษรเล็ก ศัพท์เทคนิคเยอะ ธีมมืดดูน่ากลัว มองแล้วไม่รู้ว่าหน้านี้กำลังบอกอะไร

## 🎯 เป้าหมายหลัก (paste ส่วนนี้ให้ Claude Code/Design ได้เลย)

```
ช่วยปรับ UI ของชุดหน้าจอ HTML ระบบบริหารไฟถนนนี้ใหม่ ให้ "เจ้าหน้าที่ราชการท้องถิ่นที่ไม่ใช่สายไอที" เปิดมาแล้วเข้าใจทันทีว่าหน้านี้บอกอะไรและต้องทำอะไรต่อ

หลักการที่ต้องการ:

1. ลดความหนาแน่น (de-clutter)
   - ลดจำนวนข้อมูลต่อหน้าจอ แสดงเฉพาะสิ่งที่สำคัญที่สุดก่อน ที่เหลือซ่อนใน "ดูเพิ่มเติม"
   - เพิ่ม whitespace ระหว่างบล็อก · จัดกลุ่มข้อมูลที่เกี่ยวกันให้ชัด
   - ฟอนต์ body ใหญ่ขึ้น (อย่างน้อย 15-16px) อ่านสบาย

2. บอกความหมายก่อนตัวเลข (plain-language first)
   - การ์ดตัวเลขทุกใบต้องมี "คำอธิบายภาษาคนทั่วไป" กำกับ เช่น แทนที่จะเขียนแค่ "Fleet Health 96.2%" ให้เขียน "ไฟที่ทำงานปกติ — 96 จาก 100 ดวง" 
   - ใช้ภาษาไทยเป็นหลัก ศัพท์อังกฤษเทคนิค (MTBF, SLA, telemetry, BUG) ให้มีคำไทยกำกับหรือ tooltip อธิบาย
   - แต่ละหน้ามีหัวข้อ + 1 ประโยคบอกว่า "หน้านี้ช่วยให้คุณ___" ที่ด้านบน

3. ใช้สี/ไอคอนสื่อสถานะแทนการอ่านตัวเลข
   - เขียว = ปกติ, เหลือง = ต้องระวัง, แดง = ต้องแก้ด่วน — ใช้ให้สม่ำเสมอทุกหน้า
   - มีไอคอน + ป้ายข้อความ ("ปกติ"/"มีปัญหา") ไม่ใช่แค่จุดสีเฉยๆ

4. ธีมให้ดูเป็นมิตรขึ้น
   - พิจารณาธีมสว่าง (light) เป็นค่าเริ่มต้น หรือ dark ที่ contrast นุ่มลง ไม่จัดจ้านจนล้า
   - ปุ่ม action หลักให้เด่นชัด สีเดียว รู้เลยว่ากดอะไรต่อ

5. ลำดับความสำคัญชัด (visual hierarchy)
   - สิ่งที่ต้องทำ/ผิดปกติ อยู่บนสุด เด่นสุด
   - ตารางยาวๆ → สรุปเป็นการ์ดหรือ "3 อันดับที่ต้องสนใจ" ก่อน แล้วค่อยมีลิงก์ดูตารางเต็ม

คงโครงสร้างข้อมูลและฟังก์ชันเดิมไว้ทั้งหมด — ปรับแค่การนำเสนอ/layout/ภาษา ไม่ตัด feature
```

## 📋 ปัญหาเฉพาะหน้า (แนบให้ dev ดูประกอบ)

| หน้า | ปัญหาที่เห็น | สิ่งที่ควรปรับ |
|------|--------------|----------------|
| **dashboard** | การ์ด 4 ใบบน (Fleet Health/Energy/Faults/Carbon) มีแต่ตัวเลข ไม่บอกว่าดีหรือแย่ · กราฟแน่น label ทับกัน | ใส่คำอธิบาย+สถานะสี ใต้ตัวเลขทุกการ์ด · กราฟลด element ลง |
| **faults** | ตาราง work order ยาวมาก คอลัมน์เยอะ ศัพท์ MTBF/SLA/P1-P2 ไม่มีคำอธิบาย | สรุป "งานด่วนที่ต้องทำวันนี้" เป็นการ์ดบนสุด · ศัพท์มีคำไทยกำกับ |
| **remote_control** | ปุ่มคำสั่งเยอะ Verification Flow เข้าใจยาก | แยกชัด "สั่งอะไร → ผลเป็นยังไง" เป็น 2 ขั้น มีไอคอน |
| **energy** | ตัวเลข kWh/baseline ลอยๆ ไม่รู้ว่าประหยัดหรือเปล่า | เน้นกราฟ "ก่อน-หลัง" + ข้อความสรุป "เดือนนี้ใช้ไฟน้อยลง __%" |
| **zones** | ผังต้นไม้ + ตารางซ้อนกัน งง | ทำเป็นการ์ดรายโซน คลิกเข้าดูรายละเอียด |
| **reports** | ปุ่ม export เยอะ ศัพท์ scope/package | wizard 3 ขั้น: เลือกเรื่อง → ช่วงเวลา → กดออกรายงาน |
| **backoffice** | role/entitlement เป็นศัพท์ dev | เปลี่ยนเป็นภาษาคน: "ใครเห็นอะไรได้บ้าง" |
