## 1. แนวคิดและภาพรวมแพลตฟอร์ม

### ปัญหาที่พบบ่อยใน อปท. ทั่วประเทศ

ก่อนเริ่มนำเสนอ ให้เปิดบทสนทนาด้วยการถามถึงปัญหาปัจจุบัน เพื่อสร้าง rapport และระบุ pain points ที่แท้จริง:

| ปัญหา | อาการที่พบ | ผลกระทบ |
|-------|-----------|---------|
| การจัดเก็บค่าธรรมเนียมไม่ครบ | ไม่มีระบบติดตาม ค้างชำระสะสม | รายได้หายไป 20-40% |
| กระดาษ/บัญชีด้วยมือ | Excel/สมุดบัญชี error-prone | เสียเวลา + ข้อมูลไม่ถูกต้อง |
| ไม่มีข้อมูล Real-time | ผู้บริหารไม่รู้ยอดจัดเก็บปัจจุบัน | ตัดสินใจช้า |
| ประชาชนต้องมาจ่ายที่สำนักงาน | ยุ่งยาก ใช้เวลา คิวยาว | ประชาชนไม่พอใจ ชำระล่าช้า |
| ข้อมูลกระจัดกระจาย | ค่าน้ำ ค่าขยะ ภาษีป้าย คนละระบบ | งานซ้ำซ้อน ผิดพลาด |

### แพลตฟอร์มของเรา: จุดเด่น 5 ประการ

```
1. ALL-IN-ONE  — ค่าขยะ · ค่าน้ำ · ภาษีป้าย · ใบอนุญาต ในระบบเดียว
2. CLOUD-BASED — ไม่ต้องซื้อ server ไม่ต้องดูแล IT infrastructure
3. MOBILE-FIRST — เจ้าหน้าที่ภาคสนามใช้งานผ่าน smartphone ได้ทันที
4. LINE NOTIFY — ประชาชนได้รับแจ้งเตือนผ่าน LINE ที่ใช้อยู่แล้ว
5. Multi-Tenant — ข้อมูลแต่ละ อปท. แยกกันสมบูรณ์ ปลอดภัย
```

### Architecture ระดับสูง (ใช้อธิบายให้ผู้บริหาร)

```
ประชาชน ─── LINE / Mobile App ──────────────┐
                                              │
เจ้าหน้าที่ ── Officer Web Portal ───────────┼─── Cloud Platform ─── Database (ข้อมูล อปท.)
                                              │
คนขับรถ / มิเตอร์รีดเดอร์ ── Mobile App ───┘
```

## หมวด A — ระบบเก็บค่าธรรมเนียมและบิลลิ่ง

### Core Billing & Payment Platform

> **สถานะ:** พร้อมใช้งาน (Production Ready) · รองรับทุก subscription tier

---

### A.1 ภาพรวม

ระบบหลักสำหรับบริหารจัดการค่าธรรมเนียมทุกประเภทของ อปท. ครอบคลุมตั้งแต่การออกบิล รับชำระ ออกใบเสร็จ จนถึงการติดตามค้างชำระ ทั้งหมดในระบบเดียว

**ปัญหาที่แก้ไข:**
- บิลค้างชำระสะสมหลายปีโดยไม่มีระบบติดตาม
- เจ้าหน้าที่ต้องคำนวณยอดด้วยมือ เสี่ยงผิดพลาด
- ประชาชนไม่รู้ว่าตัวเองค้างเท่าไร จนกว่าจะมาที่สำนักงาน
- ไม่มีใบเสร็จอิเล็กทรอนิกส์ ต้องพิมพ์กระดาษทุกใบ

---

### A.2 Features หลัก

#### ด้านประชาชน (Resident Portal)
- ดูบิลและยอดค้างชำระผ่าน Mobile App / LINE
- ชำระเงินออนไลน์ด้วย PromptPay QR Code
- รับใบเสร็จอิเล็กทรอนิกส์ทันที
- ติดตามประวัติการชำระย้อนหลัง
- แจ้งร้องเรียนปัญหาผ่านแอป

#### ด้านเจ้าหน้าที่ (Officer Portal)
- ออกบิลรายเดือน/รายไตรมาสอัตโนมัติ
- รับชำระเงินและออกใบเสร็จทันที (walk-in / online)
- ติดตามค้างชำระ แยกตามระดับ (เตือน → กฎหมาย)
- Dashboard สรุปรายได้ประจำวัน/เดือน/ปี
- พิมพ์ใบแจ้งหนี้ / ใบเสร็จ PDF ได้ทันที
- ระบบอนุมัติสำหรับการยกเว้น/ลดหย่อน

#### ด้านผู้บริหาร
- รายงานรายได้ real-time
- อัตราการจัดเก็บ vs เป้าหมาย
- สถิติค้างชำระแยกตามพื้นที่/โซน
- Export Excel / PDF สำหรับรายงานต่อสภา

### A.4 คำถามสำรวจความต้องการ ❓

**ข้อมูลพื้นฐาน:**
1. อปท. ท่านมีครัวเรือน/ที่ดินที่ต้องเก็บค่าธรรมเนียมทั้งหมดกี่หลัง/แปลง?
2. ปัจจุบันใช้ระบบอะไรในการออกบิลและรับชำระ? (Excel / โปรแกรมเฉพาะ / มือ)

4. มีประเภทค่าธรรมเนียมทั้งหมดกี่ประเภท? (ขยะ น้ำ ไฟ อื่นๆ)

**ปัญหาและ Pain Points:**

6. อัตราการจัดเก็บต่อปีอยู่ที่กี่เปอร์เซ็นต์ของยอดที่ควรได้รับ?
7. เจ้าหน้าที่ใช้เวลากี่วันต่อเดือนในการออกบิล + รับชำระ?
8. มีปัญหาใดในการออกใบเสร็จ/การจัดเก็บเอกสารย้อนหลัง?

**ความต้องการด้านการชำระเงิน:**
9. ปัจจุบันรับชำระแบบใดบ้าง? (เงินสด / โอน / QR)
10. ต้องการให้ประชาชนชำระออนไลน์ผ่าน Line หรือ App ได้ไหม?
11. มีนโยบายผ่อนชำระสำหรับลูกหนี้รายใหญ่ไหม?

**การรายงานและการตรวจสอบ:**
12. ผู้บริหารต้องการรายงานรูปแบบไหน? ความถี่เท่าไร?
13. มีการ Audit ภายในหรือตรวจสอบจากภายนอกไหม? ต้องการข้อมูลแบบไหน?
14. ต้องการ integrate กับระบบบัญชี / ERP ของ อปท. ที่ใช้อยู่ไหม?

## หมวด B — ระบบจดมิเตอร์น้ำ + OCR

### Meter Reading App with Optical Character Recognition

> **สถานะ:** Phase 1 (พัฒนาอยู่) · พร้อม Demo prototype · เปิดรับ Early Adopter

---

### B.1 ภาพรวม

แอปพลิเคชัน Mobile สำหรับพนักงานจดมิเตอร์ภาคสนาม — ถ่ายรูปมิเตอร์น้ำ ระบบอ่านตัวเลขอัตโนมัติด้วย AI (OCR) คำนวณค่าน้ำ และสร้างบิลได้ทันที โดยไม่ต้องพิมพ์ข้อมูลด้วยมือ

**ปัญหาที่แก้ไข:**
- จดมิเตอร์ผิดพลาดจากลายมือ/ความเหนื่อยล้าของพนักงาน
- ไม่มีหลักฐานภาพถ่ายประกอบ ทำให้โต้แย้งได้ง่าย
- ข้อมูลจดบนกระดาษ → พิมพ์เข้าระบบ → ใช้เวลานาน
- ไม่รู้ว่ามิเตอร์ชำรุดจนกว่าจะตรวจพบเอง

---

### B.2 Features หลัก

#### Meter Reader App (Mobile — สำหรับพนักงานจดมิเตอร์)
- จัดการรอบการจดมิเตอร์รายเดือน (ระบบกำหนดให้อัตโนมัติ)
- ถ่ายรูปมิเตอร์ → AI อ่านตัวเลขภายใน 2-3 วินาที
- แสดงค่าก่อนหน้า + ค่าปัจจุบัน + usage ที่คำนวณทันที
- กรอกด้วยมือได้เมื่อ OCR ไม่แม่นยำ
- บันทึก GPS พิกัดของมิเตอร์แต่ละตัวอัตโนมัติ
- รายงานปัญหา: มิเตอร์ชำรุด / เข้าไม่ถึง / สงสัยดัดแปลง
- ทำงาน Offline ได้ — sync ข้อมูลเมื่อได้สัญญาณ

#### Officer Portal — Meter Management (สำหรับเจ้าหน้าที่สำนักงาน)
- ตรวจสอบและยืนยันค่ามิเตอร์ที่ OCR อ่านมา (พร้อมดูรูปถ่าย)
- ติดตาม progress ของพนักงานแต่ละคนแบบ real-time
- รายการปัญหามิเตอร์ที่รอแก้ไข
- เชื่อมต่อกับระบบออกบิลโดยตรง

#### OCR Technology
- ใช้ Google Cloud Vision API (แม่นยำ >95% สำหรับมิเตอร์มาตรฐาน)
- Fallback: Tesseract.js (open-source, ทำงาน on-device)
- แสดง confidence score — ถ้าต่ำกว่า 80% แจ้งเตือนให้ยืนยันด้วยมือ

---

Demo 2: แสดงหน้า OCR Review ของเจ้าหน้าที่ — ดูรูปเทียบค่า OCR vs ค่าจริง

## หมวด C — ระบบภาษีป้าย

### Sign Tax Management System

> **สถานะ:** Phase 1 (พัฒนาอยู่) · พร้อม Demo prototype · เปิดรับ Early Adopter

---

### C.1 ภาพรวม

ระบบบริหารจัดการภาษีป้ายโฆษณาครบวงจร ตั้งแต่การสำรวจป้ายภาคสนาม ทะเบียนป้าย การประเมินภาษีตาม พ.ร.บ. ภาษีป้าย พ.ศ. 2510 จนถึงการออกใบเสร็จ — รองรับทั้ง 3 ประเภทป้าย

**ปัญหาที่แก้ไข:**
- ทะเบียนป้ายไม่ครบถ้วน มีป้ายนอกทะเบียนจำนวนมาก
- การคำนวณภาษีทำด้วยมือ เสี่ยงผิดพลาดและถูกโต้แย้ง
- ไม่มีหลักฐานรูปถ่ายและพิกัดป้าย
- ติดตามค้างชำระภาษีป้ายยาก

---

### C.2 กฎหมายอ้างอิง (สรุปสำหรับทีมขาย)

**พ.ร.บ. ภาษีป้าย พ.ศ. 2510** กำหนดอัตราดังนี้:

| ประเภท | ลักษณะป้าย | อัตรา | ขั้นต่ำ |
|-------|-----------|------|--------|
| TYPE 1 | อักษรไทยล้วน (หรือไทย + ภาพ/เครื่องหมาย) | 5 บาท / 500 ตร.ซม. | 200 บาท |
| TYPE 2 | อักษรไทยปนต่างประเทศ (ไทยอยู่บน) | 52 บาท / 500 ตร.ซม. | 200 บาท |
| TYPE 3 | ไม่มีอักษรไทย / ต่างประเทศอยู่บนไทย | 52 บาท / 500 ตร.ซม. | 200 บาท |

> ตัวอย่าง: ป้าย TYPE 1 ขนาด 2m × 3m = 60,000 ตร.ซม. → CEIL(60,000/500) × 5 = 600 บาท

---

### C.3 Features หลัก

#### Tax Surveyor App (Mobile — สำหรับพนักงานสำรวจภาคสนาม)
- สำรวจป้ายใหม่ที่พบ: ถ่ายรูป → บันทึก GPS → กรอกข้อมูล (ขนาด/ประเภท/เจ้าของ)
- ระบบคำนวณภาษีเบื้องต้นทันทีเมื่อกรอกขนาดครบ
- ตรวจสอบ/อัพเดทป้ายที่มีในทะเบียนแล้ว (annual check)
- รายงานการรื้อถอนป้าย

#### Officer Portal — ภาษีป้าย (สำหรับเจ้าหน้าที่สำนักงาน)
- ทะเบียนป้ายทั้งหมด พร้อม map view แสดงตำแหน่ง
- ตรวจสอบผลสำรวจจากภาคสนามก่อนอนุมัติเข้าทะเบียน
- ออกใบประเมินภาษีป้ายรายปี (batch หรือทีละรายการ)
- ระบบคำนวณอัตโนมัติตาม พ.ร.บ. — ไม่ต้องคำนวณด้วยมือ
- ออกบิลและรับชำระเชื่อมกับระบบหลัก
- รายงานสรุปรายได้ภาษีป้ายรายปี

### D.1 ภาพรวม

ระบบบริหารการจัดเก็บขยะแบบ door-to-door พร้อม Sticker System ที่ใช้แรงกดดันทางสังคมกระตุ้นให้ประชาชนชำระค่าธรรมเนียม — บ้านที่จ่ายแล้วได้รับสติ๊กเกอร์สีประจำปี ส่วนบ้านที่ค้างชำระไม่ได้รับสติ๊กเกอร์

**ปัญหาที่แก้ไข:**
- คนขับรถไม่รู้ว่าบ้านไหนจ่ายค่าขยะหรือยัง
- ไม่มีข้อมูลผลการเก็บขยะรายบ้านรายวัน
- ไม่มีระบบ incentive ให้ประชาชนจ่ายตรงเวลา

### D.2 Features หลัก

#### Driver App (Mobile — สำหรับคนขับรถเก็บขยะ)
- แสดงเส้นทางที่ assigned วันนี้ พร้อม Map
- Map pins แสดงสถานะแต่ละบ้าน: สีเขียว (จ่ายแล้ว) / สีแดง (ค้าง)
- บันทึกผลการแวะแต่ละบ้าน: เก็บได้ / ข้ามไป / ขยะไม่คัดแยก
- กด 2-3 ครั้งเสร็จ ไม่มี form ยาว

#### Sticker System (ระบบสติ๊กเกอร์)
- สีสติ๊กเกอร์เปลี่ยนทุกปีงบประมาณ (กำหนดโดย อปท.)
- บ้านที่ชำระค่าขยะ → ได้รับสติ๊กเกอร์
- คนขับเห็นสีสติ๊กเกอร์บนหน้าประตู → รู้ทันทีว่าจ่ายหรือยัง
- ป้องกันการประหยัดค่าขยะโดยอ้างว่าไม่มีคนอยู่บ้าน

#### Officer Portal — Collection Management
- สร้างและจัดการเส้นทาง + assign รถ/คนขับ
- ติดตามผลการออกรถ real-time
- รายงานบ้านที่ถูกข้ามเพราะค้างชำระ → ส่งทีมติดตาม
- สถิติการคัดแยกขยะรายเดือน/รายโซน

## 9. ขั้นตอนหลังการนำเสนอ

### 9.1 ภายใน 24 ชั่วโมงหลังประชุม

1. **ส่งอีเมลขอบคุณ** พร้อมสรุปประเด็นหลักที่พูดคุย
2. **อัพเดท CRM** ด้วยข้อมูลจาก Needs Summary Form
3. **แจ้งทีม Technical** ถ้ามีคำถาม Technical ที่ยังไม่ได้ตอบ
4. **จัดทำ Proposal เบื้องต้น** ตาม tier ที่เหมาะสม

### 9.2 ภายใน 1 สัปดาห์

1. **ส่ง Formal Proposal** พร้อม Pricing ที่ชัดเจน
2. **นัด Demo ครั้งที่ 2** (ถ้าลูกค้าต้องการ) — เน้น use case จริงของ อปท. นั้น
3. **Proof of Concept:** เสนอ Pilot 3 เดือนด้วยข้อมูลจริง (ถ้าเหมาะสม)

### 9.3 ขั้นตอน Onboarding (หลังตัดสินใจ)

```
สัปดาห์ 1-2:  Setup tenant + นำเข้าข้อมูลครัวเรือน/ทะเบียน
สัปดาห์ 2-3:  อบรมเจ้าหน้าที่ + ทดสอบระบบ (UAT)
สัปดาห์ 3-4:  Go-Live + ติดตามใกล้ชิด 30 วันแรก
เดือน 2 เป็นต้นไป: Support ปกติ + Review ผลลัพธ์รายเดือน
```

### 9.4 Red Flags ที่ควรระวัง

- อปท. ที่ไม่มีผู้รับผิดชอบด้าน IT เลย → ต้องประเมิน technical readiness
- งบประมาณไม่ชัดเจน → ต้องหาแหล่งงบก่อนดำเนินการ
- มีระบบเดิมที่ต้อง migrate ข้อมูลจำนวนมาก → ต้องประเมิน effort
- ผู้ตัดสินใจไม่ได้เข้าร่วมการประชุม → นัดประชุมใหม่ให้ครบ
